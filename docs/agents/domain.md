# Domain docs

GramLab uses a single-context layout:
`CONTEXT.md` and `docs/adr/` at the repository root.

Before exploring, read the glossary and ADRs relevant to the task.
If either is absent, proceed without creating empty documentation.

Use the glossary's canonical vocabulary in code, tests and tickets.
Keep implementation details out of the glossary.
Record newly resolved domain terms through domain-modeling.

Create ADRs for consequential trade-offs, not routine choices.
Surface conflicts with existing ADRs before changing direction.
